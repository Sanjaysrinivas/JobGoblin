01

What we're building

JobGoblin is a two-service web application — a Next.js frontend and a FastAPI backend — backed by PostgreSQL. It's multi-user (you and your friends each get isolated accounts and data) and runs entirely on free hosting tiers.

The defining principle: every external action — sending an email, messaging a recruiter, applying — requires explicit human review and approval. And the AI layer is forbidden from inventing experience, skills, or credentials; it only rephrases and reorganizes truthful content the user already provided.

📄

Analyze

Compare a resume against a job description and get an estimated, explained ATS-style match score with matched & missing keywords.

✍️

Generate

Tailored resume bullets, cover letters, and copy-ready recruiter / LinkedIn outreach — all editable, all truthful.

📊

Track

Move every application through a pipeline from saved to offer, with reminders, contacts, and a timeline.

🚫

Won't do

No auto-apply, no LinkedIn scraping or auto-connect, no silent email sending, no multi-tenant SaaS billing.

06

Core AI flow — resume × job analysis

The signature feature blends deterministic keyword matching (for the numeric score) with AI reasoning (for explanations and recommendations). The result is always labelled an estimate, never a guaranteed ATS score.

User uploads a resume → backend stores the file (local volume) and extracts plain text.
User pastes a job description and selects a resume to compare.
Deterministic pass: extract & normalize keywords from both, compute weighted category scores (keywords 30% · skills 25% · experience 20% · role 10% · education 5% · formatting 10%).
AI pass: explain gaps, distinguish missing keywords you already qualify for from qualifications you lack, and suggest truthful improvements.
Store numeric score + matched/missing keywords + recommendations; frontend renders the breakdown.
User saves the job to the tracker and moves it through the pipeline.

08

Branching & workflow

A main → dev → feature model. main stays release-ready, dev is the integration branch, and every change rides a feature branch merged via pull request.

main ────────●──────────────────────────●────▶  production-ready
        ╲
       dev ──●────●────────●─────▶  integration  ↑ PR
           ╲
   feature/* ●──●──●──▶  commits, then PR → dev

main

Always deployable. Only receives merges from dev via PR at release points.

dev

Integration branch. Feature PRs land here first and are tested together.

feature/*

One branch per unit of work, branched off dev. Opened as a PR for review.
